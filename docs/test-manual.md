# CH579M USB-HID Host + Modbus RTU 从机 测试手册

- 工程：CH579_USB_Host_HID_pro
- MCU：CH579M（ARM Cortex-M0，外部 HSE 32MHz）
- 版本：2026-08-11
- 适用范围：本手册覆盖 **上电自检、USB 键盘功能、Modbus RTU 通信、看门狗稳定性、非阻塞应答、诊断寄存器、错误注入、配置掉电保存** 的全部验收流程。

---

## 1. 测试目的

1. 验证 **看门狗修复**：9600 波特率下长期轮询不再出现 WDOG 复位循环（历史缺陷主因：`WWDG_SetCounter(250)` 误读规格，真实超时仅 ~24.6ms；现改为 `WWDG_SetCounter(12)` → 超时 ≈1.0s）。
2. 验证 **Modbus RTU 从机协议**：0x03 读保持寄存器 / 0x06 写配置寄存器完整可用。
3. 验证 **非阻塞应答**：最大 255B 应答发送期间主循环不被阻塞（USB 轮询 / 心跳照常）。
4. 验证 **工业诊断通道**：0x0082~0x0085 状态寄存器数值真实反映状态。
5. 验证 **稳定性**：长时间 50ms 轮询 + 大帧读取不丢帧、不复位。

## 3. 测试用例

约定：**发** = UART3 发送（HEX）；**收** = UART3 期望应答（HEX）；**UART1** = 调试口期望日志。帧间隔需 ≥ 3.5 字符时间（9600 下约 4ms，串口助手发送间隔取 ≥100ms 即可）。所有帧的 CRC 已经 Python 独立脚本复算。

### TC-01 上电自检（复位原因 + 配置打印）

**步骤**：上电后观察 UART1（115200）。

| 场景 | UART1 期望输出 |
| ---- | ---- |
| 上电复位（首次烧录/断电重上电） | `reset: normal` |
| 若此前被看门狗复位过 | `WDOG reset` |
| 恒打印配置 | `mb: addr=1 baud=9600`（配置未改时） |
| 启动横幅 | `MK5 USB-HID Host start` |

**判据**：出现 `reset: normal` 且无 `WDOG reset`；`mb:` 行与实际配置一致。

> 复位原因与 `mb:` 行为恒打印（不受 `APP_DEBUG_LOG` 裁剪影响），是现场排查第一手信息。

### TC-02 看门狗稳定性回归（修复核心验证）

**背景**：9600 波特率 + 2ms 轮询曾逼近看门狗上限导致复位循环；修复后超时 ≈1.0s，喂狗在每轮循环开头。

**步骤**：
1. UART3（9600 8N1）发送读 5 寄存器帧，间隔 **50ms 连续 1 分钟**：`01 03 00 00 00 05 85 C9`
2. 同时观察 UART1。

**判据**：
- 每一帧都有完整应答，无超时。
- UART1 **不出现** `WDOG reset`（全程无复位）。
- 心跳 `H:` 照常每 ~1s 打印。

### TC-03 USB 键盘功能

**步骤**：插入键盘，观察 UART1，敲击各键。

**期望**：
- 敲 `A`：`KEY:  [0] DN "A"    (mods=00)` → `KEY:  [0] UP "A"`
- 敲 `Shift+1`：`KEY:  [0] DN "!"    (mods=21)`
- 敲 `Esc`：`KEY:  [0] DN "Esc"`（多字符名称不写入 Modbus，仅日志）
- 多媒体键（接口 1）：`MEDIA: [1] DN Vol+`
- 轮询统计由 `H:` 行体现（poll/ok/nak/err）。

**判据**：按键事件均能打印；连续快速敲击不再丢键（队列已扩至 32）。

### TC-04 ASCII 帧写入规则

| 操作 | 寄存器区状态 |
| ---- | ---- |
| 敲 `ABC` | 40001=0x0041, 40002=0x0042, 40003=0x0043 |
| 按 Enter | 立即提交（余段清零，写入位复位） |
| 敲 `AB` 停 500ms+ | 空闲超时自动提交 |
| 敲 `AB` 后 Backspace | 40002 回退清零 |

### TC-05 常规 Modbus 读（0x03，5 寄存器）

**步骤**：键盘已输入 `ABC` 后发送：`01 03 00 00 00 05 85 C9`

**期望应答**：`01 03 0A 00 41 00 42 00 43 00 00 00 00 3F 2E`

| 字段 | 值 | 说明 |
| ---- | ---- | ---- |
| 01 | 从机地址 | addr=1 |
| 03 | 功能码 | 读保持寄存器 |
| 0A | 字节数 | 5 寄存器 × 2 |
| 00 41 | 40001 | 'A' |
| 00 42 | 40002 | 'B' |
| 00 43 | 40003 | 'C' |
| 00 00 00 00 | 40004~05 | 未输入为 0 |
| 3F 2E | CRC | 已复算 |

### TC-06 最大帧应答（读 125 寄存器 → 255B）＋ 非阻塞证明

**步骤**：
1. UART3 发送：`01 03 00 00 00 7D 85 EB`（读 40001~40125）。
2. **应答发送期间持续观察 UART1 心跳**。

**期望**：
- 应答完整 255B：`01 03 FA` + 250 字节数据 + CRC。
- 255B @9600 线路占用 ≈266ms，期间 **UART1 心跳 `H:` 应照常打印**（非阻塞 TX 直接证据——若为阻塞发送，心跳会整整停 ~266ms）。
- 期间敲键盘，`KEY:` 日志也应正常出现。

**判据（核心）**：`H:` 打印在应答期间不中断 → 非阻塞应答达标。

### TC-07 状态寄存器读取（0x0082~0x0085）

配置区/状态区均 **单寄存器读取**（数量必须为 1）。

| 地址 | 功能 | 发送帧（HEX） | 期望应答 `01 03 02 xx xx CRC` |
| ---- | ---- | ---- | ---- |
| 0x0082 | 上次复位原因 | `01 03 00 82 00 01 24 22` | 上电复位 `01 03 02 00 01 79 84`；看门狗复位 `01 03 02 00 02 39 85` |
| 0x0083 | 已处理帧数（16 位，高前） | `01 03 00 83 00 01 75 E2` | 随每次成功应答递增 |
| 0x0084 | CRC 错误帧数（16 位，高前） | `01 03 00 84 00 01 C4 23` | 正常 0；注入坏 CRC 后 +1 |
| 0x0085 | 按键丢弃计数（16 位，高前） | `01 03 00 85 00 01 95 E3` | 正常 0；键盘超快连发时可能非 0 |

**复位原因值编码**（`SYS_GetLastResetSta`）：

| 值 | 含义 |
| ---- | ---- |
| 0x01 | RPOR 上电复位（正常） |
| 0x02 | WTR 看门狗复位 |

**判据**：0x0083 读两次（中间多应答一帧），第二次比第一次 +1；0x0084 在注入坏 CRC 后 +1；0x0085 反映丢键。

### TC-08 错误注入

| # | 发送帧（HEX） | 期望行为 |
| ---- | ---- | ---- |
| 1 | `01 03 00 00 00 05 00 00`（坏 CRC） | 无应答；0x0084 +1 |
| 2 | `02 03 00 00 00 05 85 FA`（地址=2 不匹配） | 无应答；0x0083 / 0x0084 均不变 |
| 3 | `00 03 00 00 00 05 84 18`（广播地址 0） | 无应答（本从机不响应广播） |
| 4 | `01 04 00 00 00 05 30 09`（功能码 0x04） | 应答异常 0x01（非法功能） |
| 5 | `01 03 00 00 00 00 44 0A`（数量=0） | 应答异常 0x02（非法数据地址） |
| 6 | `01 03 00 00 00 7E 05 8A`（数量=126>125） | 应答异常 0x02 |
| 7 | `01 03 00 80 00 02 0C 22`（配置区数量=2） | 应答异常 0x02 |
| 8 | `01 06 00 01 00 41 18 3A`（0x06 写数据区） | 应答异常 0x02（非法地址） |
| 9 | `01 06 00 80 00 00 88 22`（地址=0 非法值） | 应答异常 0x03（非法数据值） |
| 10 | `01 06 00 81 00 05 19 E1`（波特率=5 非法值） | 应答异常 0x03 |

**判据**：静默场景绝不回任何字节；异常场景应答 CRC 正确、功能码带回 `0x80` 标志（`01 84 01` / `01 86 02` / `01 86 03`）。

### TC-09 0x06 写配置 + 掉电保存

**步骤**（全程 9600）：
1. 改地址为 2：发 `01 06 00 80 00 02 09 E3` → 收回显 `01 06 00 80 00 02 09 E3`。
2. 生效验证：以地址 2 读复位原因 `02 03 00 82 00 01 24 11`；以地址 1 读应无响应。
3. 恢复地址 1：以地址 2 发 `02 06 00 80 00 01 49 D1` → 回显即恢复，此后按地址 1 通信。
4. 掉电保存：写配置后断电重上电，观察 UART1 `mb:` 行与实际配置一致。

**判据**：回显正确；改址即时生效；重启后配置保持。

> 0x06 写相同值会**跳过 DataFlash 擦写**（防磨损 + 省 ~20ms 阻塞），可用重复写相同值观察应答速度无明显变慢验证（可选）。

### TC-10 波特率切换回归

1. 写波特率 19200：发 `01 06 00 81 00 01 18 22` → 回显后**立即切 19200**，主站改 19200 重连。
2. 19200 下读 5 寄存器 `01 03 00 00 00 05`（CRC 需按 19200 帧重算，见附录 `crc16()`）。
3. 恢复 9600：以 19200 写 `01 06 00 81 00 00 D9 E2` → 回显后切回 9600。
4. 切回后重复 TC-02（看门狗回归）。

**判据**：波特率即时生效；当前会话短暂掉线后重连成功；切回后稳定。

### TC-11 115200 碰撞回归（DE 即时回落专项）

**背景**：长帧应答期间若主站在 DE 回落前抢发，会撞坏应答尾字节。已优化为 DE 在字节发完瞬间回落，此用例验证优化有效。

**步骤**：
1. 写波特率 115200：以 9600 发 `01 06 00 81 00 04 D8 21` → 主站切 115200。
2. 115200 下 **50ms 循环**发 `01 03 00 00 00 7D 85 EB`（读取帧 CRC 不随波特率变）1 分钟。
3. 出现碰撞时，主站重发即可，观察是否有长期掉线。
4. 切回 9600：以 115200 写 `01 06 00 81 00 00 D9 E2`。

**判据**：115200 下轮询应答完整；碰撞重发可恢复；DE 时序无系统性撞坏。

### TC-12 长时间老化（出机前必做）

1. 9600 下 50ms 循环读 5 寄存器 **持续 1 小时**。
2. 每 10 分钟做一次 255B 大读 + 快速敲键盘。
3. 每小时读一次 `0x0082`（必须始终为 0x01 = 无看门狗复位）。

**判据**：全程无复位、无漏应答、`0x0082` 恒为 0x0001。

## 附录 B：CRC16 计算与随机帧生成（Python）

```python
def crc16(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc

def frame(hexstr: str) -> str:
    b = bytes.fromhex(hexstr)
    c = crc16(b)
    return hexstr + ' ' + format(c & 0xFF, '02X') + ' ' + format(c >> 8, '02X')

print(frame('01 03 00 00 00 05'))      # 读 5 寄存器
print(frame('01 06 00 81 00 04'))      # 改波特率 115200
```

## 附录 C：自动回归脚本示例（9600）

```python
import serial, time

def crc16(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc

def frame(h: str) -> bytes:
    b = bytes.fromhex(h)
    c = crc16(b)
    return b + bytes((c & 0xFF, c >> 8))

s = serial.Serial('COM6', 9600, timeout=0.3)
req = frame('01 03 00 00 00 05')
big = frame('01 03 00 00 00 7D')

fail = 0
t0 = time.time()
next_big = t0 + 10                # 每 10s 做一次 255B 大读
while time.time() - t0 < 60:      # 60s 稳定性
    s.reset_input_buffer(); s.write(req)
    if len(s.read(20)) != 15:
        fail += 1
    if time.time() >= next_big:
        next_big += 10
        s.reset_input_buffer(); s.write(big)
        if len(s.read(300)) != 255:
            fail += 1
    time.sleep(0.05)
print('fail =', fail)
assert fail == 0
```
